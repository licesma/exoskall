# knuth-pages — one site per project, rendered inside knuth

## The model

A project has at most ONE pages site: a Next.js App Router app at
`.knuth/pages/`, permanently in dev mode. knuth supervises its `next dev`
process and renders the site inside the app; server components read the
repo live from SQLite issues and git on every
request, so pages are always current with zero build steps.

A new "page" is a new ROUTE in this one site — never a second scaffold,
never a separate app. Explicitly not in this model: no vite, no per-page
mini-apps, no single-file HTML bundles, no `next build`, no static
export, no publish target — ever. Layouts or instructions that mention
those belong to the retired v1 model; see the collision rule below.

## First use — instantiate from the template

Look at `.knuth/pages/` first:

- **Already this template's shape** (`package.json` named `knuth-pages`,
  `src/app/`, `eslint.config.mjs`): it is the site; skip to Adding
  routes.
- **Exists but is anything else** — especially the retired v1 layout
  (`vite.config.ts`, per-slug folders, bundled `<slug>.html` files):
  **stop and surface to the user.** Never overwrite, delete, or migrate
  it on your own initiative.
- **Absent** — instantiate:
  1. Copy the whole `template/` directory that ships beside this
     SKILL.md to `.knuth/pages/` — every file, including dotfiles
     (`.gitignore`) and `package-lock.json`. No `template/` beside this
     skill? Stop and surface (this knuth install does not distribute the
     template yet); do NOT hand-scaffold a substitute — the pinned
     versions and lint config are load-bearing.
  2. Node ≥ 22.13 is required (`node:sqlite`'s floor; the template's
     `engines` field declares it — use a current LTS, 24+). Run
     `npm install` in `.knuth/pages/`.
  3. Prove the instantiation before building anything: `npm run lint`
     and `npm run typecheck` must both pass clean.

## What the template ships

- **The exact pinned stack, with lockfile**: next 16.3.4, react 19.2.8,
  tailwindcss 4.3.3 (+ typography), shadcn 4.19.1 on Radix, recharts
  3.10.1, @tanstack/react-table 9.2.4, react-markdown 10 + remark-gfm +
  shiki 4, gray-matter, date-fns, next-themes — and typescript pinned
  `~5.9` (sharp edge below; never change it).
- **Scripts**: `dev` = `NEXT_TELEMETRY_DISABLED=1 next dev -H 127.0.0.1`
  — deliberately no `-p`: port allocation belongs to knuth, and a
  scratch run passes its own port explicitly (see Seeing it rendered).
  `lint` = `eslint --max-warnings 0 src`. `typecheck` = `tsc --noEmit`.
- **Readers** in `src/shared/data/` are server-only. `database.ts` opens
  `<repo>/.knuth/issues.db` read-only using Node >=22.13 `node:sqlite` on the
  site's host. The current schema has one `issue` table and an FTS5 search
  index; `issues.ts` reads IDs, descriptions, statuses and parents. There are
  no run, event, document or gap tables. Do not invent run counts or consult
  retired stats storage. `git.ts` reads git history; `repo-root.ts` derives
  the root from the site directory (`cwd/../..`). Missing/corrupt databases
  use the page error state; do not fall back to Markdown issue files.
- Existing sites are user-owned. Review and back up their readers before
  updating them; remove retired run displays while preserving custom pages,
  navigation and styling. Template updates do not update existing sites.
- **Shell and states**: light layout, matching knuth, on the system font
  stack; `loading.tsx` / `error.tsx` / `not-found.tsx`; and the
  `src/shared/ui/empty-state.tsx` idiom — when a reader legitimately
  returns nothing, render `EmptyState`, never a blank region and never a
  crash.
- **shadcn base set** in `src/shared/ui/` (badge, button, card,
  empty-state, separator, skeleton, table, tooltip); `components.json`
  aliases already point `ui`/`lib` at `@/shared/*`.
- **Next-16-normalized meta files**: AGENTS.md / CLAUDE.md / tsconfig
  are exactly what `next dev` (Next 16) rewrites them to, so the first
  boot leaves the tree clean. The AGENTS.md block is generated by Next —
  read the docs it points to, and don't delete it (dev re-adds it).
- The root `page.tsx` renders issues and recent commits — live proof the wiring
  works, and the pattern to copy for new routes.

## Adding routes

THE LAW's `ADDING A ROUTE` section is the procedure. The close-out gate,
every time, no exceptions: `npm run lint` (zero errors, zero warnings)
and `npm run typecheck` (`tsc --noEmit`), both clean — then every touched
route fetched and read as rendered (Seeing it rendered, below).

## THE LAW

`eslint.config.mjs` enforces this mechanically — `npm run lint` fails on
violations. Do not edit the lint config to make an error go away.

```
KNUTH PAGES LAW — .knuth/pages/ site architecture (v2)

THE MAP (closed world — the linter rejects any file outside it)
  src/app/               Routes (Next App Router): page/layout/loading/error/route files,
                         plus _components/ per route for page-local pieces.
  src/widgets/<name>/    Blocks used by 2+ routes. One folder per widget, flat inside.
  src/shared/ui/         Reusable dumb UI. shadcn installs here (components.json "ui" alias -> @/shared/ui).
  src/shared/lib/        Pure TS: types, formatters, cn(). No React state, no I/O.
  src/shared/data/       ALL reads: fs, git, sqlite, HTTP. Server-only; first line: import 'server-only'.

IMPORT DIRECTION (lint-enforced; anything not listed below is an error)
  route      -> widgets, shared/*         app root    -> widgets, shared/*
  widget     -> shared/ui, shared/lib     shared/ui   -> shared/ui, shared/lib
  shared/lib -> shared/lib                shared/data -> shared/data, shared/lib
  NEVER: route<->route, widget<->widget, anything -> app/, widget -> shared/data.

DATA FLOW
  page.tsx is a server component: it calls shared/data readers and passes plain,
  serializable props down. Client components never read or fetch anything.
  Live data = router.refresh() on an interval, never client fetch/SSE.

FILES
  One exported React component per .tsx; filename = kebab-case of the component
  (deps-chart.tsx -> DepsChart). Exception: shared/ui kit files may export a family.
  kebab-case for every file and folder ([id], (group), _components allowed under app/).
  Imports: same folder './x'; everything else '@/...'. Never '../'. No index.ts barrels.

ADDING A ROUTE
  1. mkdir src/app/<route>/ with page.tsx: server component, reads via shared/data, composes.
  2. Page-local components -> src/app/<route>/_components/ ('use client' only on leaves).
  3. The moment a 2nd route needs a component, move it to src/widgets/<name>/.
  4. New data need -> a typed reader in src/shared/data/, never inline in a page.
  Root '/' page composes widgets/shared only (no _components at the app root).

npm run lint must pass with zero errors before any close-out.
eslint-disable only with a trailing reason: // eslint-disable-next-line <rule> -- <why>
```

## Prose-only rules — what the linter cannot catch

Same force as THE LAW; these fall to you because no rule fires on them:

1. Filename ↔ exported component name correspondence (`deps-chart.tsx` must export
   `DepsChart`) — no maintained rule matches export names to filenames; lint only
   enforces the kebab-case shape.
2. `import 'server-only'` as the first line of every `shared/data` file (defense in
   depth; the structural leak is already lint-blocked, but future refactors aren't).
3. `'use client'` only on leaf interactive components — Next's build catches *illegal*
   server/client mixes, but nothing flags an unnecessary `'use client'` on a page.
4. Promote-on-second-use timing — lint can't count "how many routes need this yet".
5. Serializable props only across the server→client boundary — Next errors at runtime,
   not at lint time.
6. Readers return plain typed objects — nothing stops a reader exporting a live
   sqlite handle or an fs stream except review.
7. Aliased/dynamic I/O: `const f = globalThis['fetch']`, `EventSource`, `WebSocket`,
   `XMLHttpRequest`, `import(variable)` — the restricted-global/property rules match
   direct syntactic use only. (EventSource/WebSocket/XMLHttpRequest *could* be added to
   `no-restricted-globals` as hardening; aliases still escape.)
8. shadcn components must be added via the CLI into `shared/ui`, not hand-copied
   elsewhere (once elsewhere, layer rules apply, but the provenance rule is prose).
9. The `-- reason` requirement on eslint-disable comments (addable later via
   `@eslint-community/eslint-plugin-eslint-comments` `require-description`; prose until then).
10. `router.refresh()` as the only live-refresh mechanism — an api route + EventSource
    polling loop would slip past the fetch ban.
11. Widget folders staying flat and small — internal structure depth isn't linted.

## Sharp edges — where trained priors are wrong

1. **TanStack Table v9 — the loudest trap in the stack.** v9 renamed the
   core API: `useReactTable` → `useTable`, row-model options → a
   `tableFeatures()` / `features` object, and `flexRender` is now a
   component. LLM priors and nearly all tutorials show the v8 API and
   will not compile against v9. Write from the current v9 / shadcn
   data-table docs only, and never "fix" v9-style code back toward v8.
2. **Tailwind v4 is config-less.** `@import "tailwindcss"` plus a
   `@theme` block in `globals.css`; there is no `tailwind.config.js` to
   edit. Pre-2025 snippets that reach for a config file are wrong here.
3. **Chart color tokens are raw values.** Consume them as
   `var(--chart-1)` (raw OKLCH), never `hsl(var(--chart-1))` — the old
   wrapping silently produces black charts.
4. **recharts is client-only and needs real height.** Every chart sits
   behind `'use client'` and receives its data as props; give the chart
   container an explicit height class — `ResponsiveContainer` in a
   zero-height parent renders nothing. v3 removed the internal-state
   props, so v2-era tooltip tricks don't port.
5. **react-markdown is synchronous; shiki is async.** Async rehype
   plugins (`@shikijs/rehype`) do NOT work inside react-markdown.
   Pattern: pass an async server `CodeBlock` component via
   `components={{ code: … }}` that calls shiki (RSC allows async
   component children), or run a unified pipeline in the server
   component and inject the HTML.
6. **Create the shiki highlighter once, at module level.** It loads WASM
   and grammars; never construct it per request.
7. **The server→client boundary takes serializable props only.** Map
   sqlite rows and git output to plain objects/arrays before handing
   them to any `'use client'` chart or table.
8. **typescript stays `~5.9`.** typescript-eslint (inside
   eslint-config-next) hard-rejects TypeScript 7, which kills
   `npm run lint` — the LAW's gate. The `~5.9` pin is not a stale
   dependency; never "upgrade" or "fix" it to 7.x.
9. **shadcn: `add` yes, `init` never.** `npx shadcn add <component>`
   honors the `components.json` aliases and lands in `@/shared/ui`.
   Never re-run `shadcn init` — it ignores pre-set aliases and drops
   files in the wrong layout. The project is already initialized.

## Seeing it rendered — the last gate before any close-out

Lint and typecheck prove the tree, not the render: a route that throws
answers **HTTP 200** (the error boundary is client-rendered; the server
still streams a page), so a status code proves nothing on its own. The
site has at most ONE dev server — Next's per-directory lock refuses a
second `next dev` in `.knuth/pages/` whatever its port — and its address
is published in `.next/knuth-dev.port` (one line, the port) by whoever
started it: knuth when it serves the site, or an earlier run of this
skill. When that file exists and `curl -s -o /dev/null
http://127.0.0.1:$(cat .next/knuth-dev.port)/` connects, that server is
the site's: read through it and never start, stop, restart or port-guess
it. For each route you touched, `curl -s
http://127.0.0.1:$(cat .next/knuth-dev.port)/<route>`, then the log tail:
`tail -n 40 .next/knuth-dev.log` when `.next/knuth-dev.pid` exists (knuth's
own server writes there), else `tail -n 40
.next/dev/logs/next-development.log` (Next's own file, which every dev
server writes). The check is the **body and the log**, not the code: the
body must contain text only that route renders (its own heading, a label
you know it prints — never `<title>`, the shell, or "No such page", which
every response embeds for the not-found template), and the log tail after
your GETs must carry no `⨯` line (a render failure logs `⨯ Error:
<message>` with `at <Component> (src/app/…)` under it). A missing marker,
a `⨯`, a non-200 or a refused connection is a defect: fix it, fetch
again, and quote the marker you saw and the log's `GET /<route> 200` line
in your close-out. When nothing is serving — no port file, or a refused
connection (a stale file: remove it) — start the site's server yourself,
in `.knuth/pages/`: `npm run dev -- -p <port>` with a free port you picked
(40000–49999; the script binds `-H 127.0.0.1`), in the background with
its output to a file, wait for its `✓ Ready` line, then publish it:
`printf '%s\n' <port> > .next/knuth-dev.port` — the port file ONLY, never
`.next/knuth-dev.pid` (that file names a process knuth itself started, and
knuth's next open kills what it names). If instead it exits with "Another
next dev server is already running", the `Local:` URL it prints is the
site's server: publish that port and read through it. Yours is now THE
server for the site: knuth adopts it when the user opens Pages (the view
says "served by an existing dev server") and your edits hot-reload
through it. At close-out, stop it — kill your `npm run dev` process and
remove `.next/knuth-dev.port` — **unless knuth is serving through it**:
`.next/knuth-adopted.pid` exists and names the same pid as `.next/dev/lock`
(`[ "$(cat .next/knuth-adopted.pid 2>/dev/null)" = "$(grep -oE
'"pid":[0-9]+' .next/dev/lock 2>/dev/null | cut -d: -f2)" ]`), in which
case leave it running and say so — the port file stays, knuth lets the
server go when its view closes, and the next run of this skill finds it by
the port file. Never report its URL as the site's address.
